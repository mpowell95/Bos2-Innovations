Rows D and K are the ones that matter. It is the proposed fix — the same base64 image, just wrapped in an inline <svg>. If D is red like A/B/C, the host is blocking the data: scheme itself and wrapping it in SVG cannot help. If D is green, the host is only filtering <img src> and the fix works.

Row K tells us which. It injects the identical data URI with JavaScript, after the page loads, so a server-side HTML filter never sees it. If K is green but A is red, the host is stripping markup on upload and rows D/E/F are worth trying. If K is red too, the browser itself is refusing data: images and no amount of rewriting will help — the slides have to stop being data URIs altogether.
